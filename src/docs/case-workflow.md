# 案例研判流程与接口

最后更新：2026-10-26。本文说明当前实现及其边界，完整政务业务质量验收见[能力路线图](agent-capability-roadmap.md)。

## 运行与模式选择

Windows 从仓库根目录启动：

```powershell
.\src\.venv\Scripts\python.exe -m src.main --host 127.0.0.1 --port 8000
```

也可双击仓库根目录的 `XiaochiLauncher.exe`。EXE 依赖同目录的 `src` 和本地虚拟环境；修改代码后停止并重新启动服务，再刷新网页。macOS/Linux 使用 `src/.venv/bin/python -m src.main --host 127.0.0.1 --port 8000`。密钥继续由仓库根目录私有 `.env` 加载，系统环境变量优先；本轮没有新增专用政策库或动态密钥。

- **即时答复**（`rough`）：现有信息直接答复，不追问、不逐项核验来源。必要时最多一次轻量搜索、三个工具调用；不确定的信息保留为条件或未知。
- **互动研判**（`interactive`）：先厘清情景和疑点，必要时每轮最多两问，提供选项、自由输入、暂不清楚及暂不补充入口；不逐项核验政策原文、版本和效力。与即时答复共用轻量工具预算。
- **审慎研判**（`precise`）：必要时先进行最多两问的交互，再使用官方检索、原文读取和按需核验能力，分析版本、适用条件与例外。无法取得的证据如实保留。

网页首次默认互动研判，并记住选择。API 省略 `mode` 仍默认为 `precise`；CLI 同样保留审慎研判流程。模式是请求级设置，不会修改其他会话。

## 工作人员使用流程

1. 提交案例描述及已有材料，不要求先填完整调查表。每轮最多五个附件，单文件最多 25 MB。
2. 可选填初步处理倾向：倾向予以支持、倾向不予支持、尚未确定或自行说明。倾向用于确定分析重点，不能代替事实和政策判断，也不能排除相反依据。
3. 互动研判和审慎研判只问会影响判断的关键问题。每题可选一个选项并补充文字，也可暂不补充。只有点击提交后的内容进入记录；已回答或明确跳过的问题不反复要求回答。
4. 随时点击侧栏 **按现有信息分析**，结束本轮追问，按当前模式处理已提交信息。审慎研判仍执行必要政策核验；点击不意味着材料已齐备、陈述已证实或处理意见已成立。
5. 后续继续补充时保存新版本，保留原陈述和修正。切换模式复用回答、材料和初步处理倾向。此前轻量模式的结论不能自动视为已核验依据。

系统要求将用户陈述、材料内容、争议事项和未知信息分开处理；缺失条件采用明确分支，不补造事实。当前案例状态保存的是提交记录、问题/回答和分析版本，尚不是具备事实核验及结论依赖追踪的完整研究档案。

## 答复阅读与输入区

已有助手答复后，输入框切换为两行、最小 52px 的紧凑高度，继续输入可按内容增高至 240px；首页保留四行、最小 112px 的输入框。成功提交后“初步处理倾向”自动收起，已提交倾向继续保存在案例记录中；需要修改时可重新展开，不必重复填写。

新答复在服务端完成推理、工具执行和正文净化后才返回，前端随后渐进显示这份完整的最终正文。用户可以立即显示全文；历史恢复不重播，复制与朗读仍取完整答复。切换会话或继续提交会结束旧展示任务；手动向上阅读时暂停跟随，回到底部后恢复。滚动跟随当前正文末尾，避开固定输入区的遮挡。系统启用减少动态效果、页面在后台或展示过程中转入后台时，直接显示全文。渐进展示通常在 2–4.5 秒内完成，期间可继续操作。

这是最终正文的客户端呈现方式，不是模型实时 token streaming，不会提前暴露内部思考或工具结果，也不代表模型首字时间缩短。处理耗时与模型完成时间不由展示动画改写。

答复末尾不再自动保留独立的固定“草稿，供审核”“草稿未审核”等有限尾句变体。AI 参考提示仍保留；材料未经核实、政策效力待核验、条件缺失等与具体案例有关的说明仍应显示。正文句子、引号、原文摘录、引用块及代码不泛删；用户明确要求照录该尾句时保留，但“不要添加/不要保留”不会触发保留。此规则统一用于新答复、CLI、公开历史与口播；旧记录仅在展示时处理，不改写原始记录。用户需要的草稿正文仍保留。

## 消息 API

先 `POST /api/conversations` 新建会话，再向 `POST /api/conversations/{conversation_id}/messages` 发送 JSON。示例为虚构测试情景，不包含真实业务资料。

```json
{
  "message": "某企业希望办理一笔跨境业务，目前材料尚未齐全，请先梳理需要关注的事项。",
  "mode": "interactive",
  "tendency": "undecided",
  "tendency_note": "主要不确定业务应如何定性。"
}
```

可用字段：

- `message`：最多 20,000 字符，默认空字符串。
- `attachments`：本会话上传接口返回的附件 ID 数组，最多五项。
- `mode`：`rough`、`interactive` 或 `precise`；默认 `precise`。
- `action`：默认 `respond`；`analyze_existing` 表示本轮停止追问、分析现有资料。
- `answers`：最多两项，每项含 `question_id`、可选的 `selected_option`、`text` 或 `skipped`。问题 ID 必须取自当前响应，选项必须来自该问题；不接受过期问题、重复 ID 或伪造选项。
- `tendency`：`undecided`、`support`、`oppose`、`custom`，不填表示未新增倾向；`undecided` 是用户明确提交“尚未确定”。
- `tendency_note`：最多 2,000 字符，提供时必须同时提供 `tendency`。
- `request_id`：可选 UUID，用于查询本轮进度。

回答当前问题时，将下例的占位内容替换为最新 `clarification_questions` 返回值；选择与文字可以同时提交，跳过时不可同时发送选项或文字。

```json
{
  "mode": "interactive",
  "answers": [
    {
      "question_id": "从当前响应复制问题ID",
      "selected_option": "从该题复制实际选项",
      "text": "可补充已有材料能够说明的情况。"
    }
  ]
}
```

已有案例时直接开始分析可发送：

```json
{"mode":"precise","action":"analyze_existing"}
```

也可同时提交本轮 `answers`、材料或描述。空案例不能凭空分析。正常 `respond` 请求至少需要文字、材料、回答或明确倾向之一。发送失败不提交案例状态，前端恢复草稿。

响应包括 `conversation_id`、`answer`、`answer_html`、`clarification_questions`、`citations`、`case_state`、`mode` 和 `elapsed_seconds`。旧 `related_questions` 字段保留为空数组；不要据此生成三条兜底问题。即时答复和 `analyze_existing` 的 `clarification_questions` 均为空。

`case_state` 保存提交版本、待答问题、问题历史、初步处理倾向和分析版本。用户记录标为 `user_statement`，不能当作经核实的事实。元数据与公开正文分开；内部思考、工具和专家中间内容不进入公开答复。

## 引用与效力展示

引用卡片保留可取得的文件名称、发布机关、文号、URL、条款、发布日期和施行日期；未取得的字段保留空缺。效力区分现行有效、尚未施行、已废止/失效、部分修改或替代、待核验，不根据发布日期或“废止”等关键词自动判定整份文件状态。

引用 URL 必须来自实际工具结果、用户已提交的 URL 或可信政策库记录；用户提供链接仍只是待核实线索。正文显式引用政策但没有取得对应来源时显示“来源未取得，待核实”。过滤只针对来源链接，不泛删代码块、引文或用户要求的答复草稿。

当前实现将以下信息分开：

- `source_status` 表示只有线索，还是本轮已读取原文。
- `proposed_validity` 是模型建议，仍未核验。
- `validity` 在没有可信后端记录时保持 `pending`；`checked_at` 不伪造当前核验时间。
- 引用规范化接口可接收带相匹配官方证据的可信政策库历史记录，保留其原始核验时间及证据，并注明本轮未重新核验效力。历史状态不保证当前有效，也不保证本案适用。

审慎研判会查找、读取和分析核验线索，但读取原文、提取到“废止”文字或获得模型判断都不能自动产生“已核验有效”的状态。新引用在没有可信记录时仍显示待核验；默认库为空，尚未建立正式资料入库及自动匹配链路，也没有人工审批界面或完整法律效力认证流程。历史案例还需要检查业务发生时点、当时版本和过渡条款。

## 空政策库的范围

`src/policy/store.py` 提供 SQLite 数据层；默认由 `create_app()` 在 `src/workspace/policy_data/policy.sqlite3` 初始化。自定义会话存储时，数据库位于会话目录的上一级 `policy_data` 子目录。

本轮严格保持空库：无演示或真实政策导入、无采集任务、无前端入口、无 HTTP 导入 API。测试夹具仅写临时测试目录。后端具备文件/条款记录、中文全文索引、文号精确匹配、领域/地区/时间筛选、版本关系、效力证据和更新记录；写入/替换/删除会同步索引。检索结果仍需判断本案适用性，未查到禁止规定不能推定可以办理。

语义检索通过可注入 embedding 提供方和模型标识预留接口，默认未配置；不能把目前的全文检索称为已完成语义 RAG。政策动态不会自动成为政策正文或可信效力记录。公开资料入库、审核、采集来源管理、历史快照及完整更新流水线属于后续建设。

## 政策动态

提交问题异步触发相关资讯查询，不阻塞主答复。查询只使用预设粗粒度业务主题，原始案例、企业账号或材料正文不进入这一路资讯查询。此边界不改变聊天模型处理用户提交内容的既有方式。

- `GET /api/conversations/{id}/policy-news`：读取动态快照。可选 `date_from`、`date_to`（`YYYY-MM-DD`）、`category`、`domain`、`region`；日期筛选针对发布日期；页面“本周”按上海时区从周一开始，“本月”按上海时区的日历月计算，已覆盖跨月、跨年边界测试。
- `POST /api/conversations/{id}/policy-news/refresh`：手动异步刷新，返回 HTTP 202。JSON 可带 `question`、`domain`、`region`、`category`；`question` 仍只用于提取粗业务主题。
- 分类支持 `announcement`、`upcoming`、`amendment`、`interpretation`、`news`、`other`、`all`；领域支持 `forex`、`tax`、`commerce`、`development`、`all`。地区使用页面提供的值，不将发布机关地址当作政策适用地区。

动态展示原始来源、已有发布日期、明确取得的施行日期、系统归纳和来源性质；日期不明时留空。即将施行分类只使用明确日期线索，仍不是效力核验。新闻与搜索摘要不能直接作为处理依据，未找到正式文件时保留为待核实线索。当前动态模块不进行政策与具体案例的精确适用性判定；用户选择“核查与本案的关系”后，将来源和核验请求填入咨询区，经用户发送再进行分析，不自动改写结论。

动态独立缓存在内存中，重启后清空；失败保留上次成功结果，并显示失败状态与上次成功时间。服务存活时每六小时刷新已存在的主题订阅，不会因启动而抓取全部政策，也不是 Windows 计划任务。新闻刷新会消耗已配置搜索服务的调用额度。

### 输入区收起与展开

输入区右上角提供收起/展开按钮，使用 `aria-expanded` 与 `aria-controls` 标明状态。折叠仅隐藏输入区域，保留当前页未提交文字、材料、倾向及澄清选项；生成中也可切换。按现有信息分析仍可提交这些内容，失败时恢复草稿，错误提示在折叠区外可见。快捷事项自动展开，新建咨询恢复展开；不跨刷新保存未提交草稿。
