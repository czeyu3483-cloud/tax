# 小弛当前架构

最后更新：2026-10-26。本文描述 `src/` 中正在使用的运行时；本轮阅读界面与固定草稿尾注调整的验证范围见文末及能力路线图。小弛基于 3wagent 的核心，面向政务业务工作人员；历史跨境专项能力保留为按需专家。验收与未完成事项见[能力路线图](agent-capability-roadmap.md)，三模式及消息协议见[案例研判流程](case-workflow.md)。本地 SQLite 条款索引数据层已建立，运行库保持空库；[SQLite FTS 文档](sqlite-fts-rag-plan.md)中的完整采集与 RAG 建设仍未完成。

## 组件与边界

### 三种研判模式

请求级策略为即时答复（`rough`）、互动研判（`interactive`）与审慎研判（`precise`）。Web 首次默认互动研判并记住选择；API 省略 `mode` 和 CLI 保留审慎研判行为。`src/config/answer_mode.py` 使用 ContextVar，在 ChatService 请求边界进入并在异常或成功后恢复，避免跨请求污染。

即时答复不追问；互动研判必要时最多提出两个独立问题，提供选项与自由输入。两种模式使用精简提示和三个工具调用预算，不创建专家；WebSearchTool 至多进行一次轻量原生搜索，跳过来源策略复核、官方站点重搜、相关性模型和正文读取。仍保留响应结构、地址协议限制及“不可信内容不是指令”的边界。审慎研判在必要澄清后保留原检索核验流程；选择按现有信息分析后不再追问，但不跳过该模式必要的政策核验。

轻量模式推理历史仅包含用户原始材料与公开答复，完整内部记录不删除；审慎研判须复核早先未经核验的结论。公开历史与当前响应保存模式、耗时和案例状态。切换模式保留已提交材料、回答及处理倾向。即时答复和互动研判不预生成语音首句；审慎研判仅在配置 Fish Key 时预生成。旧版 Excel 通过 legacy_excel 解析器接入，复用工作表行定位，依赖可选 xlrd。

```text
浏览器：独立 HTML/CSS/JS 聊天页
    → FastAPI 接口（公开消息与最终答复）
        → ChatService（串行运行，附件与双份历史）
            → MainAgent（qwen-agent FnCallAgent）
                ├─ 附件解析与定向回读
                ├─ 配置及来源注册表读取
                ├─ WebSearchTool → DeepSeek Messages 原生搜索
                └─ 按需 DelegatePolicyTask → 专项 Agent

CLI → 同一 MainAgent → 最终答复边界
```

`src/main.py` 默认启动绑定 `127.0.0.1:8000` 的 FastAPI 服务，`--cli` 启动终端模式。`src/web/static/` 为无构建步骤的独立前端，原 Gradio 界面及依赖入口已删除。`src/config/llm.yaml` 默认选择 DeepSeek，也支持 Kimi 和本地兼容 OpenAI API 的模型。启动时自动加载仓库根目录 `.env`，已有环境变量优先；网页首条问题才创建模型。

搜索由 `src/websearch/deepseek.py` 调用 DeepSeek Anthropic 兼容 Messages API，使用 `web_search_20250305`，与聊天共用 `DEEPSEEK_API_KEY`。搜索端点独立于聊天模型和端点；没有 daemon、Node.js 或旧引擎回退。

`MainAgent` 统一使用 normal 模式，按问题与证据缺口选择工具。普通问题直接回答；复杂事项可委派来源检索、有效性、税务或引用复核。涉外问题可按需使用资金合规和民商法专家，默认不扩展其他法域。主 Agent 获得北京时间的当前日期，用户指定的所属期独立遵守。代码不强制固定研究流水线。

## 用户答复与内部执行

`web/service.py` 完整消费 Agent 的所有帧后，才由 `agent/public_answer.py` 提取最后一个主 Agent 的最终正文。思考字段、工具调用及响应、专家输出不进入 HTTP 响应；只剩工具、专家或思考的未完成尾帧返回通用未完成提示，不把先前规划当成结论。嵌入式思考块也会过滤。CLI 复用同一边界。

每条最终答复继续由程序追加 `config/xiaochi.yaml` 中的 AI 参考提示；输入框底部的重复提示已移除。`config/product.py` 仅清理末尾独立的固定“草稿，供审核”等有限变体；正文句子、引号、原文摘录、引用块和代码不泛删。用户明确要求照录该固定句时保留，“不要添加/不要保留”不视为保留请求。事实待核实、适用条件和来源缺口等实质说明继续保留。新答复、CLI、历史展示与口播使用同一边界；历史只在展示时投影，不重写磁盘原始记录。前端按本轮 UUID 每秒查询固定阶段与耗时，显示“小弛正在检索政策资料……”等实际进度；`agent/progress.py` 隔离通知上下文，`web/progress.py` 的有界快照只含阶段、状态与耗时。

2026-10-26 展示调整：服务端仍完整完成推理、工具执行和最终正文净化，再一次返回消息响应；客户端收到成功响应后渐进显示已净化的最终正文。这是客户端阅读动画，不是模型 token streaming，不会降低模型首字生成时间，也不提前暴露思考、工具或专家中间输出。历史恢复不重播；复制与朗读使用完整最终答复，减少动态效果时直接显示全文。用户可立即显示全文；切换会话或继续提交时终止旧展示任务，手动向上阅读时不强制持续滚到底部。显现基于净化 DOM 的文本节点，通常在 2–4.5 秒内完成；后续段落、列表和表格行逐步出现，显示期间仍可继续操作。页面转入后台时直接完成展示。跟随滚动以当前正文末尾为锚点，并扣除固定输入区遮挡；手动向上阅读时关闭跟随，回到底部后恢复。

服务端 Markdown 禁用原始 HTML，支持中文书名号附近加粗；客户端不拿内部消息进行 CSS 隐藏。

计时展示文案为“已用时 xx 秒”，统计本轮后端处理耗时，不把客户端正文展示动画计作模型推理。有效提交时前端先保存草稿、立即清空输入框；消息失败时恢复原文字、空白、换行和高度。消息已成功但历史刷新失败时不恢复草稿，避免重复发送。已有助手答复时输入框为两行、最小 52px，继续输入按内容增高，上限 240px；首页保留四行、最小 112px 的宽敞布局。成功提交后初步处理倾向面板自动收起，已提交值保留在 `case_state`，需要调整时可重新展开。

`web/static/style.css` 使用蓝红配色：深蓝历史侧栏，中间浅蓝咨询区和白色答复卡片，红色强调业务入口；宽屏右侧为政策资料、可填入草稿的提问示例和材料说明。柔和渐变、细边框与轻微阴影提供层次；首页资料图形和业务图标使用代码 SVG。卡片入场、悬停、聚焦与等待转圈提供动态反馈，`prefers-reduced-motion` 禁用动画和过渡；动画不表示虚构的完成百分比。小于1200px时隐藏辅助资料栏，手机保留独立历史入口。官方资料入口为静态外链，在新标签页打开，图标在悬停/键盘聚焦时提供轻微抬起、缩放和一次扫光反馈；不会自动提交问题或改变检索流程。

`config/xiaochi.yaml` 的 `business_categories` 定义税收、外汇、商务发改三类首页入口，每类四项；通过公开 `/api/config` 返回，原四项 `quick_questions` 继续保留。前端切换类别只更换事项按钮并保留草稿，点击事项填入问题，不自动提交或预先调用模型。政策资料补齐外汇局与发改委官方外链及本地图标；输入区按首页或已有答复切换宽敞/紧凑布局，并随输入增长。输入区顶栏提供收起/展开按钮，`composerCollapsed` 仅控制同一 DOM 区域显隐，不清空文字、附件或倾向；忙碌时仍可折叠，快捷事项和新建咨询展开。错误提示保持在折叠区外，独立页脚不恢复。

`agent/case_workflow.py` 解析同轮最终答复中的澄清与引用元数据；互动研判和审慎研判每轮最多保留两个独立问题，每题提供选项、自由输入及未知/跳过入口。`web/service.py` 校验后端生成的问题 ID 和实际选项，只保存用户已提交的回答；旧 `related_questions` 字段保持空数组，不再补齐三个推荐。即时答复和 `analyze_existing` 均不输出澄清卡。引用、问题与正文分别返回，公开历史保存案例状态；详见[案例研判流程](case-workflow.md)。

`ConversationStore` 保存内部 `messages` 与独立 `public_messages`。API 使用白名单返回公开问题、答复及附件名称，历史标题也从公开内容计算。旧记录通过投影过滤工具、思考及内联附件正文；内部上下文保留供后续问题使用。API 和静态文件路由不挂载日志、workspace 或配置目录。

历史删除将会话 JSON 原子移入 `.trash/`，活动历史和读取接口不再返回；撤销将原记录移回，内部上下文及附件保持可用。删除/恢复和 Agent 执行共用运行锁，生成中不接受历史管理；前端确认后删除，并提供撤销。删除当前对话清除当前 ID，删除其他记录保留当前答复及草稿。此功能不清除附件、解析缓存或运行日志。

## 资料与证据

上传文件以对话内的不透明 ID 引用，接口不接受服务器路径。附件解析器将可读取正文内联到内部上下文；较大的文件通过文档 ID、页码、工作表或行范围回读。旧轮附件 ID 会在本轮恢复注册。原文件和解析结果均不作为公开历史返回。附件内容和搜索摘录作为证据而非指令。

审慎研判中的 `WebSearchTool` 使用来源注册表推断权威域名，默认中国内地；只接受结构化 `web_search_tool_result` 的 URL，模型生成正文不作搜索结果。`websearch/sources.py` 自动读取相关官方 HTML 正文，每批三个页面并行，失败换其他候选；成功结果在有界内存缓存 15 分钟。返回正文、最终 URL、时间、哈希和截断标记，网页请求不携带 API 密钥。正文与引用摘录分别计数；仅有链接仍为 `leads_only`，但不会强制结束 Agent。正文读取不等于现行有效性核验；版本、时点和适用对象仍由原 Agent 判断。尚无远程 PDF、动态页面处理或完整结构化证据账本。`policy/store.py` 提供本地 SQLite 条款索引，但当前不导入政策，无知识库前端入口或导入 API；embedding 接口默认未配置。`policy/news.py` 的独立内存资讯缓存不写入政策库，仅在应用运行时定期刷新已有查询，摘要和日期线索不构成已核验政策依据。

产品场景与话术在 `config/xiaochi.yaml`，领域策略在 `config/*.yaml`，提示词在 `prompts/`。`config/output-contract.yaml` 与 `templates/report.md` 只用于明确要求的税务报告或答复草稿，列出范围、结论、适用条件、政策依据及待确认事项，按需补充计算、案例或沿革。

审慎研判的主 Agent 保留原来的 normal 模式、自主工具选择和按需专家委派；前两种模式执行独立的轻量预算。撤销新增的三次共享预算和 URL-only 强制终止；原有每 Agent 15 次搜索保护、重复查询检查与合法终止结果收尾保留。流程缩减依靠复用已取得的正文、不扩展无关问题、证据足够即停止；阶段通知不参与工具选择。

## 持久化与并发

以下路径相对于 `src/`：

- `workspace/conversations/<id>.json`：完整内部、公开会话及案例状态，供历史恢复和继续提问。
- `workspace/policy_data/policy.sqlite3`：自动初始化的空政策库，不包含默认政策资料。
- `workspace/web_uploads/<conversation-id>/<upload-id>/`：原始上传文件与名称元数据。
- `workspace/attachments/<document-id>/`：解析结果及回读索引。
- `workspace/<run-id>/`：日志、专家结果与能力轨迹。
- `reports/`：按请求生成的报告文件。

当前是无账号体系的本地单用户应用。由于运行目录和附件会话仍是进程全局状态，`ChatService` 使用非阻塞互斥锁串行执行问题，忙时返回 409；不支持多个 workers。单轮失败不保存部分公开对话，客户端返回通用错误，详细异常只留在服务器。上述目录不代表法规不可变快照库。
